# Decision log

Chronological record of the main design decisions (2026-10-08), with the evidence behind each.

| # | Decision | Alternatives considered | Why |
|---|---|---|---|
| 1 | **Connectome: FlyWire v783 (female brain)** | MaleCNS v1.0 (brain + VNC, 166,700 neurons); BANC (female brain + VNC) | The only *validated, executable* whole-brain model (Shiu et al. 2024) is built on FlyWire; its annotations (Schlegel et al. 2024) name every sensory class and descending neuron we need. MaleCNS/BANC include the VNC but no validated dynamics; motor control below the neck (CPGs, asynchronous flight muscle) is not captured by an LIF model anyway, so a robot interface at the descending-neuron level is the honest choice. |
| 2 | **Neuron model: the Shiu et al. LIF model, unmodified** | flyvis (task-trained, visual only); FlyGM (RL-trained graph network); building a new trained model | Keeps the brain *connectome-determined* (one free parameter fitted by the original authors). Trained models would make the behaviour partly a learned policy. |
| 3 | **Re-implement the LIF model on the GPU** | Run Brian2 in the loop | Brian2 needs minutes per simulated second and ~3 GB RAM per process; closed-loop control needs ≥ real time. The block-synchronous, event-driven port runs at ~10x real time and is bit-reproducible; validated against the original code at four drive levels (r = 0.9991–0.9999). |
| 4 | **Whole brain, no reduction** | Extracting a sub-circuit between chosen inputs and outputs | The full model fits easily in GPU memory and runs faster than real time, so reduction is unnecessary; it would also hide off-target effects such as the olfactory runaway. |
| 5 | **Physics: MuJoCo 3.15** | Isaac Sim, Gazebo/PX4, PyBullet, Webots, FlyGym | Lightweight pip install, deterministic, site-force rotors with actuator dynamics, wheel servos, ray casting, offscreen cameras, runs in the same Python process as the PyTorch brain. |
| 6 | **Robot body: 7-inch X quad + 4 independently driven skid-steer wheels** | 2 driven wheels + casters; passive cage wheel (HyTAQ); separate rover | Recognisable FPV quad, symmetric, simple to fabricate; skid steer needs no steering servo; wheels double as landing gear; rolling costs ~5x less energy per metre than flying (docs/hardware.md). |
| 7 | **Interface at identified sensory neurons and descending neurons** | Driving DNs directly from sensors; reading motor neurons | Sensory → brain → DN keeps the brain's own computation in the loop; DNs are the brain's output to the body and have literature-defined roles (as in the Eon Systems demo, but here with the body replaced by a robot). |
| 8 | **Olfaction excluded from the brain interface** | Driving ORNs, PNs or lateral-horn neurons | The pathway atlas showed a self-sustaining runaway state for any olfactory, thermo- or hygrosensory input (even 5 Hz on 35 ORNs, or one PN at 50 Hz). Documented as a finding; odor task run with the baseline + a negative control. |
| 9 | **Obstacle sensing by ToF ranging → LC16** | EMD expansion from the camera | EMD expansion rose only ~0.3 m before pillars and was symmetric for pillars dead ahead; both controllers collided. Ranging is a realistic sensor (VL53L8CX) and is labelled as a functional approximation. |
| 10 | **Contact retreat reflex in the low-level layer** | None; brain-driven backing via MDN | Without it both controllers stayed pinned against obstacles; MDN is not driven by our inputs in the model. Shared by all controllers, so comparisons are fair. |
| 11 | **Left/right symmetry calibration of input gains** | Leave the brain's asymmetry; symmetrise the connectome | Equal bilateral drive produced a strong turning bias (FlyWire is one asymmetric individual). Calibrating per-side sensor gains is the minimal, transparent fix; the uncalibrated brain is an ablation. |
| 12 | **Add DNp15 (DNHS1) to the steering read-out** | Only walking-steering DNs (DNa01/02, DNg13, DNb06) | With the yaw gyro failed, HS/H2 → DNa02 gave no stabilisation (H2 even destabilising); the atlas and Erginkaya et al. (2025) show HS + contralateral H2 converge on DNp15. Adding it produced a working optomotor loop and also improved obstacle avoidance on tuning seeds (5/8 → 7/8). |
| 13 | **Saccade generator off** | Integrate-to-threshold saccades | Triggered by single-cell DN noise; flight course 0/4 with vs 3/4 without on tuning seeds. |
| 14 | **LC16 onset at approach rate 0.3 s⁻¹ (was 0.5)** | — | Earlier avoidance; with #12: flight 4/4, course 8/8 on tuning seeds. Interface frozen after this (commit `ba6fa7f`); evaluation uses seeds ≥ 1000. |
| 15 | **Fix: Brian2 conditional-write semantics** | — | Validation against the original code revealed that input arriving during refractoriness must be discarded. Engine fixed (commit `abab370`), all results regenerated; the frozen interface was re-checked on tuning seeds without changes. |
| 16 | **Rendering: Mesa llvmpipe on WSL2** | d3d12 GPU path, EGL | EGL unavailable on WSL2; d3d12 was 6–13x slower than llvmpipe for MuJoCo's draw-call pattern. |
| 17 | **Browser viewer replays recorded episodes** | Live streaming only | Works as a static page (GitHub Pages) without a GPU; every frame is recorded simulation output. |
| 18 | **Memory-capped background jobs** | — | Brian2 with 16 workers exhausted the 15 GB WSL2 VM and killed the session; all heavy jobs now run under `systemd-run --user -p MemoryMax=…`. |
| 19 | **Project name "Connectocopter"** | Drosodrone, Melanocopter | No GitHub repositories with that name; describes connectome + copter. |
| 20 | **Fix: odor baseline turned downwind** | — | The first evaluation run of `odor_plume` scored 1/12. Inspection showed a sign error in the baseline's upwind term (it turned *away* from the wind). The baseline was rewritten as a textbook surge-and-cast tracker (surge upwind on contact, cast crosswind with growing width when the plume is lost) and re-tuned on tuning seeds 0–9 only; the faulty evaluation records are kept in `results/benchmarks/superseded/`. The connectome results are unaffected (it has no odor channel). |
| 21 | **Engineered optomotor baseline for the yaw task** | Compare the connectome only against a baseline with no optic-flow feedback | The general baseline has no optomotor term, so on `yaw_stabilization` it was only a floor. A fair comparison needs an engineered optic-flow → yaw controller on the same EMD features; its gain (900) was chosen by a sweep over 0–1800 on tuning seeds 0–2 (`scripts/dev/tune_optomotor_baseline.py`, `results/tuning/optomotor_baseline_gain.json`). A first evaluation run with an unswept guess (k = 150) scored 5/12; it is kept in `results/benchmarks/superseded/` and replaced by the tuned gain, as the baseline should get the same tuning effort as the connectome interface. |
| 22 | **Report collision-free success for the obstacle course** | Success = reaching the goal only | Reaching the goal does not require zero contacts, and the connectome relies more on the shared contact-retreat reflex than the baseline does; reporting only goal-reaching would flatter it. |
